# Алгоритм движения роботов

## Cooperative A\*

- Для MVP предлагаю использовать алгоритм **Cooperative A\***. Это расширение алгоритма поиска пути A\*, которое позволяет учитывать перемещения других роботов и резервирование клеток во времени.

- Для возможного дальнейшего развития и замены алгоритма на более продвинутые, но сложные в реализации решения необходимо разработать планировщик как независимый модуль. Это позволит при необходимости заменить алгоритм в зависимости от возникающих задач и проблем (потребление ресурсов, скорость работы, оптимальность маршрутов, блокировки, разрешение конфликтов).

## Правила движения

- Маршруты роботов строятся последовательно, в порядке очереди, с учётом времени (`tick`). Клетка резервируется на каждый `tick`, когда робот находится в ней
- Все роботы выполняют запланированные действия синхронно в рамках одного `tick`.
- Перемещение на одну клетку или ожидание занимает один `tick`.
- Робот имеет четыре возможные положения: `UP` | `RIGHT` | `DOWN` | `LEFT` .
- Робот может перемещаться только вперёд относительно своего текущего направления. Изменение направления движения возможно исключительно через поворот на месте. Стоимость поворота на 90° - 1 `tick`. Боковое движение и движение задним ходом не допускаются.
- После достижения конечной точки робот продолжает резервировать занимаемую клетку на неопределённое время, пока не получит новый согласованный маршрут.

### Состояние робота

- `IDLE` Робот свободен, не имеет задания и стоит на месте.
- `MOVING` Робот выполняет маршрут: перемещается или поворачивается.
- `WAITING` Робот выполняет запланированное действие WAIT, ожидая освобождения клетки.
- `BLOCKED` Не удалось построить безопасный маршрут с учётом других роботов.
- `NO_PATH` До цели нет геометрического пути из-за статических препятствий.
- `FAULT` Неисправность или другая ошибка. _доработка фичи со сломанным роботом_

### Возможные действия робота на каждом tick

- Переместиться на одну клетку вперед (`FORWARD`).
- Остаться на месте (`WAIT`).
- Повернуться налево на 90° (`TURN_LEFT`).
- Повернуться направо на 90° (`TURN_RIGHT`).

### Проверка перед FORWARD

- Находится ли следующая клетка в пределах карты.
- Есть ли в ней статическое препятствие.
- Зарезервирована ли клетка другим роботом на следующий `tick`.
- Не происходит ли одновременного обмена клетками между двумя роботами (`SWAP`).

### Проверка перед TURN_LEFT, TURN_RIGHT и WAIT

- Не зарезервирована ли текущая клетка другим роботом на следующий tick.

## Конфликты

### Взаимная блокировка

**Алгоритм действий:**

1. Движение запускается только после успешного построения и проверки согласованных маршрутов.
2. Если построить безопасные маршруты для всех затронутых роботов не удалось, выполняется перепланирование.

### Маршрут не найден

**Алгоритм действий:**

1. Сохранить текущие позиции и направления роботов.
2. Изменить порядок планирования, например переместить робота, для которого не удалось построить маршрут, в конец очереди.
3. Пересчитать маршруты с текущих позиций:
   - Если все маршруты найдены, запустить выполнение.
   - Если хотя бы один маршрут не найден, попробовать ещё несколько вариантов порядка планирования.
   - Если после нескольких попыток маршруты так и не удалось построить, перевести задание в состояние `BLOCKED`, отобразить причину в журнале событий и карточке задания. Дальнейшее разрешение ситуации требует участия оператора.

### Блокировка пути роботами без задания

- Робот без задания резервирует текущую клетку на неопределённое время. Это может привести к блокировке прохода или доступа к пункту выдачи.
- В связи с этим необходимо продумать механизм перемещения свободных роботов в места, где они не будут создавать препятствия, либо предусмотреть специальную зону ожидания (хаб) для роботов.

### Отложить или обсудить

- **Поломка робота.** Определить, необходимо ли моделировать неисправности роботов в MVP или этот функционал можно добавить позже.
- **Хаб для роботов.** Определить необходимость специальной зоны ожидания для свободных роботов.
- **Остановка робота.** Поскольку разрабатывается симуляция и маршруты рассчитываются до начала движения, незапланированная остановка может происходить при блокировке или отсутствии безопасного маршрута. Запланированное ожидание (`WAIT`) является частью маршрута и не считается блокировкой. Робот без задания (`IDLE`) также остаётся на месте.
- **Выбор ближайшего свободного робота.** Ранее обсуждалось, что задания назначаются конкретным роботам, а не автоматически ближайшему. Если потребуется определять ближайшего робота к пункту приёма, можно использовать тот же алгоритм планирования маршрутов и выбирать робота с минимальным расчётным временем прибытия.
- робот заезжает на пункт или становится рядом для выгрузки?

# API robot-routing

```typescript
interface RobotRouting {
  plan(input: PlanningInput): PlanningResult;
  replan(input: PlanningInput): PlanningResult;
  validate(input: ValidationInput): ValidationResult;
}
```

## 1.Координаты и направление

```typescript
type Position = {
  x: number;
  y: number;
};

type Direction = 'UP' | 'RIGHT' | 'DOWN' | 'LEFT';

type Action = 'FORWARD' | 'TURN_LEFT' | 'TURN_RIGHT' | 'WAIT';
```

## 2.Робот

```typescript
type RobotStatus = 'IDLE' | 'MOVING' | 'WAITING' | 'BLOCKED' | 'NO_PATH' | 'FAULT';

type Robot = {
  id: string;
  position: Position;
  direction: Direction;
  status: RobotStatus;
};
```

## 3.Карта

```typescript
type Grid = {
  width: number;
  height: number;
  obstacles: Position[];
};
```

## 4.Цель

```typescript
type Goal = {
  type: 'STATION';
  stationId: string;
  approachPositions: {
    position: Position;
    direction: Direction;
  }[];
};
```

## 5.Входные данные

```typescript
type PlanningInput = {
  grid: Grid;
  currentTick: number; //текущий такт симуляции.
  robots: Robot[]; //все роботы на карте, включая свободных.
  requests: {
    //роботы, которым нужно построить маршруты.
    robotId: string;
    goal: Goal;
  }[];
  existingRoutes?: RobotRoute[]; //маршруты, которые уже выполняются и должны учитываться.
};
```

## 6.Результат планирования

```typescript
type RouteStep = {
  //состояние робота после выполнения действия на указанном тике.
  tick: number;
  action: Action | 'START';
  position: Position;
  direction: Direction;
};
type RobotRoute = {
  robotId: string;
  steps: RouteStep[];
};
type PlanningResult =
  | {
      success: true;
      routes: RobotRoute[];
      priorityOrder: string[];
    }
  | {
      success: false;
      reason:
        | 'NO_PATH' // цель недостижима на статической карте
        | 'BLOCKED' // безопасный согласованный план не найден с учётом других роботов
        | 'SEARCH_LIMIT'; // исчерпан лимит поиска
      robotIds: string[];
      attempts: number;
    };
```
