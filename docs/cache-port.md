# Порт кэша

Use case зависит только от `CachePort` в [apps/api/src/cache/application/ports/cache.port.ts](../apps/api/src/cache/application/ports/cache.port.ts). Nest, ioredis и конкретный адаптер в application-код не импортируются.

## Контракт

```ts
get(key: string): Promise<CacheValue | null>
set(key: string, value: CacheValue, ttlMs: number): Promise<void>
delete(key: string): Promise<void>
```

`null` из `get` — промах или истёкшая запись. Сохранить `null` нельзя: корень значения не бывает `null`. Внутри объекта и массива `null` допустим. Значение — JSON: строка, конечное число, boolean, массив или объект. Циклы, `undefined`, `NaN` и разреженные массивы отвергаются до записи.

Ключ — непустая строка. TTL — целое число миллисекунд больше нуля. Это логический ключ use case. Префикс `CACHE_KEY_PREFIX` добавляет только Redis-адаптер, в ключ его не включают.

Порт не проверяет форму payload под конкретный use case. После `get` вызывающий код сам разбирает значение. Чужой или битый payload для этого use case — промах: запись удаляют и читают источник истины.

`ping` в порт не входит. Проверка живости Redis для health — метод `RedisCache.ping()` у уже открытого клиента.

## Ошибки

Сбой кэша — `CacheError`. Текст фиксированный и не содержит URL, секрет или payload. Смотреть нужно `kind`:

| `kind`           | Когда                                          |
| ---------------- | ---------------------------------------------- |
| `invalid_key`    | Пустой ключ                                    |
| `invalid_ttl`    | TTL не положительное целое число миллисекунд   |
| `invalid_value`  | Значение нельзя сохранить                      |
| `corrupt`        | Из хранилища прочитан неразборчивый payload    |
| `unavailable`    | Хранилище недоступно                           |
| `command_failed` | Команда отклонена хранилищем по другой причине |

Порт не глотает ошибку. Решает use case. Для склада чтение и запись кэша при `CacheError` не ломают запрос и не отменяют уже выполненный commit. Другая ошибка, не `CacheError`, пробрасывается.

## Как подключить

`CacheModule` не глобальный. Модуль, которому нужен кэш, импортирует его и инжектит `CachePort`. Повторный import того же модуля даёт тот же экземпляр.

Один `CACHE_DRIVER` на процесс, подмены нет.

- `memory` — `MemoryCache` в памяти процесса. Redis не открывается. Обязателен `CACHE_MEMORY_MAX_ENTRIES`. `REDIS_URL` и `CACHE_KEY_PREFIX` не нужны. При переполнении вытесняется самая старая запись. Запись живёт до TTL, отдельного таймера нет.
- `redis` — `RedisCache`. Обязательны `REDIS_URL` и `CACHE_KEY_PREFIX`. Клиент создаёт и закрывает адаптер: `connect` на старте модуля, при ошибке старта соединение рвётся и процесс не поднимается, на остановке `quit` не дольше 1 с. Пока повторное подключение возвращает задержку, тот же клиент поднимается сам. После исчерпания повторов нужен перезапуск процесса.

Кэш не источник истины. В него кладут то, что уже прочитано или сохранено в БД, с коротким TTL. Команда склада сначала завершает транзакцию, потом удаляет ключи. Неудачное удаление не делает commit неуспешным.

Ключи склада заданы в [apps/api/src/modules/warehouse/application/queries/warehouse-cache.policy.ts](../apps/api/src/modules/warehouse/application/queries/warehouse-cache.policy.ts): `warehouse:details:v1:{id}` и `warehouse:list:v1:all`, TTL 30 с. Карта в этот кэш не пишется. Новый use case заводит свой ключ с версией в имени и не переиспользует эти строки.
