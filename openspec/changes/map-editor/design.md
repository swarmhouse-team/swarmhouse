# Design

## Context

См. proposal.md — Why. Прототип `apps/web/app/[locale]/prototype-map/WarehouseDemo.tsx` работает с `col/row` и захардкоженными объектами. Контракт `WarehouseMapBody` из `@robots/shared` задаёт `width`/`height` и массивы `obstacles`, `robots`, `stations`; координаты объектов — поля `x`/`y`. Поле `position` есть только в командах редактирования (`EditWarehouseMapOperation`), в теле карты его нет. Монорепо построен по FSD: `apps/web/src/{shared,entities,features,widgets,pages}`, публичный API слайса — через `index.ts`.

## Goals / Non-Goals

**Goals:**

- Страница редактора с раскладкой, которая совпадает с прототипом макета.
- Центральная область подстраивается под размер окна.
- Активный инструмент переключается.
- Сводка внизу считается из фикстуры контракта.
- Страница открывается без ошибок SSR.

**Non-Goals:**

- Виджет карты на Konva, зум колесом, перетаскивание, выделение объектов (см. proposal.md).
- Превью карты для списков.
- Storybook.
- Сохранение и редактирование объектов, подключение к API.
- Изменение контракта `@robots/shared`.

## Decisions

### Страница в слое `pages`, заглушка вместо виджета

Страница `pages/map-editor` собирает шапку, тулбар, центральный слот, панель и футер. Центральный слот — `div`, который занимает всё свободное место (`flex-1`, `min-h-0`) и тянется вместе с окном. Когда появится виджет `warehouse-map`, он встанет в этот слот без изменения раскладки.

Альтернатива: сразу сделать виджет на Konva. Отклонено: это отдельный объём работы, который не нужен для текущей раскладки.

### Фикстура в `@robots/shared`

Фикстура `validWarehouseMap` лежит в `packages/shared/src/fixtures/warehouse-map.ts` и экспортируется через `fixtures/index.ts`. Её переиспользуют страница, будущий виджет и Storybook. Фикстура соответствует `warehouseMapBodySchema`.

Альтернатива: держать моки внутри `pages/map-editor`. Отклонено: виджет и Storybook не смогли бы переиспользовать данные.

### Сводка из фикстуры

Футер считает размер (`width` × `height`) и количество `stations`, `robots`, `obstacles` из фикстуры. Подсчёт вынесен в чистую функцию, чтобы проверять его без рендера.

### Состояние инструмента через `createModelStore`

Активный инструмент хранится в `pages/map-editor/model/editor-tool-store.ts` через существующий `createModelStore` (`shared/lib/store`). Тулбар только переключает значение, действий над картой нет.

### Заглушки панелей и зума

Панель вкладок и кнопки зума — только UI. У кнопок зума есть пропсы для значения и колбэков, но реальной логики зума нет. Значение приходит пропсом, колбэки на уровне страницы пустые.

### Страница без ошибок SSR

Маршрут `app/[locale]/map-editor/page.tsx` — серверный компонент, который рендерит `MapEditor`. Интерактивные части (тулбар, вкладки, кнопки) — клиентские компоненты с `'use client'`. Обработчики создаются внутри клиентских компонентов, чтобы не передавать функции через серверную границу.

## Risks / Trade-offs

- [Расхождение с макетом по вёрстке] → Сверка с макетом по скриншоту и ручная проверка на `/ru/map-editor`.
- [Заглушки могут долго остаться заглушками] → Пропсы зума и инструментов задаются сразу, чтобы подключение логики не меняло разметку.
- [Медленный диск для dev-сервера] → Next предупреждает «Slow filesystem» на диске F; к этому изменению не относится.

## Migration Plan

1. Добавить `packages/shared/src/fixtures/warehouse-map.ts` и экспорт из `fixtures/index.ts`.
2. Добавить `pages/map-editor` и маршрут `app/[locale]/map-editor/page.tsx`.
3. Удалить `app/[locale]/prototype-map/` вместе с `WarehouseDemo.tsx` и ссылками на него.
4. Откат: вернуть удалённую папку из git (`git checkout -- apps/web/app/[locale]/prototype-map`).
