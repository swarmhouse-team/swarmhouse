# Spec Delta

## Purpose

Веб-клиент показывает интерфейс на русском или английском, включая тексты ошибок API и валидации форм.

## ADDED Requirements

### Requirement: Языки

Веб-клиент SHALL поддерживать языки `ru` и `en`. Язык по умолчанию — `ru`.

#### Scenario: Язык не определён

- **WHEN** у пользователя нет cookie `NEXT_LOCALE`, а `Accept-Language` не содержит ни `ru`, ни `en`
- **THEN** интерфейс показывается на русском

### Requirement: Язык в URL

Каждая страница SHALL открываться по адресу с префиксом языка: `/ru/...` или `/en/...`. Префикс определяет язык страницы.

#### Scenario: Адрес с префиксом

- **WHEN** пользователь открывает `/en`
- **THEN** страница показывается на английском

#### Scenario: Несуществующая страница

- **WHEN** пользователь открывает `/en/xyz`
- **THEN** сервер отвечает 404, текст страницы на английском

#### Scenario: Неподдерживаемый язык

- **WHEN** пользователь открывает `/de`
- **THEN** `de` считается путём без префикса: перенаправление на `/ru/de`, там 404

### Requirement: Адрес без префикса

Запрос без префикса SHALL перенаправляться на тот же путь с префиксом. Язык выбирается по порядку: cookie `NEXT_LOCALE`, затем `Accept-Language`, затем `ru`.

#### Scenario: Есть сохранённый выбор

- **WHEN** пользователь с cookie `NEXT_LOCALE=en` открывает `/`
- **THEN** его перенаправляет на `/en`

#### Scenario: Только Accept-Language

- **WHEN** пользователь без cookie и с `Accept-Language: en-US` открывает `/`
- **THEN** его перенаправляет на `/en`

### Requirement: Переключатель языка

На каждой странице SHALL быть переключатель языка. Выбор языка открывает ту же страницу с другим префиксом и сохраняет язык в cookie `NEXT_LOCALE`.

#### Scenario: Смена языка

- **WHEN** пользователь на `/ru` выбирает English
- **THEN** открывается `/en`, интерфейс на английском, cookie `NEXT_LOCALE=en`

#### Scenario: Текущий язык

- **WHEN** открыта страница `/en`
- **THEN** в переключателе выбран English

### Requirement: Ссылки сохраняют язык

Внутренние ссылки и переходы SHALL вести на страницы с текущим префиксом языка.

#### Scenario: Переход по ссылке

- **WHEN** на странице `/en` пользователь переходит по внутренней ссылке
- **THEN** новый адрес начинается с `/en`

### Requirement: Атрибут lang

`<html lang>` SHALL совпадать с языком страницы уже в ответе сервера.

#### Scenario: Английская страница

- **WHEN** запрошена страница `/en`
- **THEN** HTML-ответ содержит `<html lang="en">`

### Requirement: Тексты только из словарей

Все тексты интерфейса SHALL браться из словаря текущего языка: тексты, подписи, `aria-label`, `placeholder`, тосты, заголовок и описание страницы. Данные пользователя не переводятся.

#### Scenario: Заголовок страницы

- **WHEN** открыта страница `/en`
- **THEN** `<title>` на английском

### Requirement: Запрет текста в JSX

Линтер SHALL падать, если в JSX веб-клиента текст написан прямо в коде. Тесты и stories не проверяются.

#### Scenario: Текст в JSX

- **WHEN** в компоненте написано `<button>Сохранить</button>`
- **THEN** `pnpm lint` завершается с ошибкой

### Requirement: Одинаковые ключи в словарях

Словари `ru` и `en` SHALL содержать одинаковые ключи без пустых значений. Это проверяют тесты в CI.

#### Scenario: Ключ только в одном словаре

- **WHEN** ключ есть в `ru.json`, но нет в `en.json`
- **THEN** тесты падают и называют этот ключ

#### Scenario: Пустой перевод

- **WHEN** значение ключа — пустая строка
- **THEN** тесты падают и называют этот ключ

### Requirement: Ошибки API переводятся по коду

Текст ошибки API SHALL выбираться по `code` ошибки на текущем языке. Поле `message` от сервера пользователю не показывается. Для неизвестного кода показывается общий текст ошибки.

#### Scenario: Известный код

- **WHEN** API вернул `{ "code": "SERVICE_UNAVAILABLE", "message": "Database is unavailable" }` на странице `/ru`
- **THEN** пользователь видит русский текст для `SERVICE_UNAVAILABLE`

#### Scenario: Неизвестный код

- **WHEN** API вернул код, которого нет в словаре
- **THEN** пользователь видит общий текст ошибки на текущем языке

#### Scenario: Нет сети

- **WHEN** запрос не дошёл до сервера на странице `/en`
- **THEN** пользователь видит английский текст для `NETWORK_ERROR`

### Requirement: Код в ошибках полей API

Каждый элемент `details` в ошибке `VALIDATION_ERROR` SHALL содержать необязательное поле `code` с кодом нарушенного правила. Старые клиенты продолжают работать.

#### Scenario: Пустое обязательное поле

- **WHEN** API получил пустое поле `name` с минимальной длиной
- **THEN** ответ содержит `details: [{ "path": "name", "code": "too_small", "message": "..." }]`

### Requirement: Ошибки валидации переводятся по коду

Ошибки полей форм и ошибки полей из ответа API SHALL показываться на текущем языке по коду правила. Сообщение, явно заданное в схеме, считается ключом словаря.

#### Scenario: Ошибка формы

- **WHEN** на странице `/en` введена строка короче минимума 3
- **THEN** под полем английское сообщение с числом 3

#### Scenario: Ошибка поля от API

- **WHEN** API вернул `details[].code = "too_small"` для поля формы
- **THEN** под этим полем переведённое сообщение для `too_small`

#### Scenario: Своё сообщение в схеме

- **WHEN** в схеме сообщение задано ключом словаря и правило нарушено
- **THEN** показывается перевод этого ключа
